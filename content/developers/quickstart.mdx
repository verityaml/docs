## Prerequisites

- Node.js 22+
- npm 10+
- A PostgreSQL database with pgvector extension (RDS or local)

## Setup

<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone <repo-url>
    cd verity
    ```
  </Step>
  <Step title="Install dependencies">
    ```bash
    npm install
    ```
    The project is a monorepo using npm workspaces. Dependencies are hoisted to the root `node_modules/`.
  </Step>
  <Step title="Configure environment variables">
    ```bash
    cp frontend/.env.example frontend/.env.local
    ```

    Edit `frontend/.env.local` with your credentials:

    ```env
    DATABASE_URL=postgresql://...        # PostgreSQL connection string
    BETTER_AUTH_SECRET=...               # Random secret for BetterAuth
    VOYAGE_API_KEY=pa-...                # Voyage AI — embeddings (voyage-law-2)
    ANTHROPIC_API_KEY=sk-ant-...         # Anthropic — document parsing
    ```

    Optional variables (for AWS deployment):

    ```env
    AWS_S3_BUCKET=...                    # S3 bucket for file storage
    SQS_QUEUE_URL_PARSE=...              # SQS queue URLs for background jobs
    EMAIL_FROM=...                       # Defaults to "Verity <noreply@verityaml.com>"
    ```
  </Step>
  <Step title="Run database migrations">
    ```bash
    npm run db:migrate
    ```
  </Step>
  <Step title="Seed the regulatory knowledge base">
    ```bash
    npm run db:seed
    ```
    This populates the FFIEC sections, FinCEN advisories, deficiency patterns, and red flags. Embedding generation is rate-limited for the Voyage AI free tier (~22s between calls).
  </Step>
  <Step title="Start the dev server">
    ```bash
    npm run dev
    ```
    The app will be running at `http://localhost:3000`.
  </Step>
</Steps>

## Project structure

```
verity/
├── frontend/          # Next.js app — UI pages and API routes
│   ├── src/
│   │   ├── app/       # App Router (pages + API routes)
│   │   ├── components/
│   │   ├── lib/       # Auth, storage, utilities
│   │   └── proxy.ts   # Session gate (Next.js 16)
│   └── e2e/           # Playwright E2E tests
│
├── backend/           # Shared library — schema, config, jobs
│   └── src/
│       ├── config/    # REGULATION_CONFIG
│       ├── db/        # Drizzle schema + migrations + seed
│       ├── jobs/      # Lambda job functions + shared helpers
│       ├── queue/     # Queue abstraction (SQS)
│       └── lib/       # Embeddings, knowledge search, storage
│
├── desktop/           # Tauri v2 desktop app (macOS)
│   ├── src-tauri/     # Rust source, Tauri config
│   └── package.json
│
├── infra/             # AWS CDK infrastructure
│   ├── lib/           # Stack definitions
│   └── cdk.json
│
└── docker/            # Production Docker build
```

The `frontend/` package is the Next.js application with all API routes. The `backend/` package is a shared library — not a server. The `desktop/` package is a Tauri v2 macOS app that wraps the web UI. All packages share types and config at build time via npm workspaces.

## Commands

| Command | Description |
|---------|-------------|
| `npm run dev` | Start Next.js dev server |
| `npm run build` | Build both packages for production |
| `npm test` | Run all unit tests (backend + frontend) |
| `npm run lint` | Lint the frontend |
| `npm run db:generate` | Generate Drizzle migration files |
| `npm run db:migrate` | Apply pending migrations |
| `npm run db:seed` | Seed the regulatory knowledge base |
| `npm run test:e2e` | Run Playwright E2E tests (headless) |
| `npm run test:e2e:ui` | Run E2E tests with Playwright UI |
| `cd desktop && npx tauri dev` | Run desktop app in dev mode |
| `cd desktop && npx tauri build` | Build unsigned .dmg |
| `cd infra && npx cdk synth` | Synthesize CloudFormation templates |
| `cd infra && npx cdk deploy` | Deploy infrastructure to AWS |
