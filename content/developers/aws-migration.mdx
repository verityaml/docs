Verity is migrating from Vercel + Supabase + Inngest to AWS-native services. This page covers the target architecture, the 8-phase migration plan, and cost analysis. The migration is funded by $5k-25k in AWS credits.

For the current production architecture, see [Architecture diagrams](/developers/architecture-diagrams).

## Target architecture

The target stack replaces Vercel, Supabase, Inngest, and Resend with AWS-native services. It adds **CloudFront** (CDN), **AWS WAF** (application firewall), and **Shield Standard** (DDoS protection) at the edge. Estimated cost: **~$120-150/mo** (covered by AWS credits).

```
Browser → Route 53 → AWS WAF → CloudFront (edge cache)
                                  │
                                  ▼
                        ALB (origin, /api/health)
                                  │
         ┌────────────────────────┼─── VPC 10.0.0.0/16 ───────────────────┐
         │                        ▼                                        │
         │  Public Subnets    Private Subnets                              │
         │  ├── NAT Gateway   ├── ECS Fargate (Next.js, 0.25 vCPU)       │
         │                    ├── RDS PostgreSQL 16 (pgvector)            │
         │                    └── Lambda (4 functions)                     │
         └─────────────────────────────────────────────────────────────────┘
                          │              │              │
                   ┌──────┼──────────────┼──────────────┼──────┐
                   ▼      ▼              ▼              ▼      ▼
                  S3    SQS+DLQs     Bedrock        SES    CDK Pipelines
                 files  4 queues   Claude Sonnet   email   (self-mutating)
```

### Key decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Compute | ECS Fargate | Closest to Vercel DX, SSR+API routes work natively |
| Database | RDS db.t4g.micro | $13/mo vs Aurora Serverless v2 $43/mo minimum |
| Storage | S3 (single bucket) | Same signed URL pattern as Supabase Storage, cheaper |
| Auth | Keep BetterAuth | Runs inside Next.js, zero migration effort |
| LLM | Amazon Bedrock | Claude Sonnet 4.6 via IAM auth, no API keys |
| Embeddings | Keep Voyage AI | Legal-domain-specific, re-embedding cost too high |
| Background jobs | SQS + Lambda | Each Inngest function becomes a Lambda + queue |
| Email | SES (replacing Resend) | AWS-native, covered by credits |
| CDN + WAF | CloudFront + WAF | Edge caching, rate limiting, SQLi/XSS protection |
| IaC + CI/CD | CDK + CDK Pipelines | Self-mutating pipeline with cdk-nag compliance gate |

## Migration plan

The migration runs in 8 phases over approximately 5 weeks. Each phase has a verification checklist and rollback plan. Vercel stays live throughout — cutover is a DNS switch.

### Phase 0: Preparation

- Create AWS account, enable Bedrock model access (Claude Sonnet 4.6 in us-east-1)
- Initialize CDK project at `infra/` in repo root
- Add `GET /api/health` endpoint

### Phase 1: Infrastructure via CDK

All infrastructure defined in a single CDK stack (`infra/lib/verity-stack.ts`):

- **Networking** — VPC with public/compute/data subnets, NAT Gateway, security groups
- **Edge** — CloudFront distribution, WAF web ACL (rate limiting + managed rules), ACM certificate
- **Data** — RDS PostgreSQL 16 with pgvector, S3 bucket
- **Messaging** — 4 SQS queues + 4 DLQs
- **Compute** — ECR repo, ECS Fargate cluster + service, ALB
- **Functions** — 4 Lambda functions + SQS triggers
- **CI/CD** — CDK Pipelines (self-mutating: source, synth, cdk-nag, staging, manual approval, production)

### Phase 2: Database migration

Migrate from Supabase Postgres to RDS via `pg_dump`/`pg_restore`. Verify pgvector embeddings intact across all 5 tables. Run Drizzle migrations to ensure clean state.

### Phase 3: Storage migration

Replace `@supabase/supabase-js` with `@aws-sdk/client-s3` across 17 route files. New `frontend/src/lib/storage.ts` abstraction for upload, download, delete, and signed URL operations.

### Phase 4: Background jobs (SQS + Lambda)

Replace Inngest with SQS + Lambda. Each Inngest function becomes a single Lambda:

| Lambda | Timeout | Replaces |
|--------|---------|----------|
| `verity-parse-examination` | 15min | `parse-examination` with step-based checkpointing |
| `verity-auto-match-evidence` | 5min | `auto-match-evidence` |
| `verity-propagate-evidence` | 1min | `propagate-evidence` |
| `verity-backfill-evidence-links` | 2min | `backfill-evidence-links` |

<Note>
Inngest's `step.run()` wrappers are removed. Each Lambda is a single execution unit — no step function checkpointing needed. Idempotency preserved via `onConflictDoNothing()` on DB inserts.
</Note>

### Phase 5: Bedrock provider swap

Single-file change — swap the AI SDK provider:

```typescript
// Before
const { anthropic } = await import("@ai-sdk/anthropic");
const model = anthropic("claude-sonnet-4-6");

// After
const { bedrock } = await import("@ai-sdk/amazon-bedrock");
const model = bedrock("us.anthropic.claude-sonnet-4-6-v1");
```

Replace Resend with SES. Verify domain with DKIM + SPF records. Keep the graceful no-op pattern.

### Phase 7: CI/CD (two-track model)

Two separate CI/CD pipelines:

**Track 1 — App CI/CD (GitHub Actions):**
- PR checks: lint, test, E2E, build, `cdk diff` comment
- On merge: OIDC auth, Docker build, ECR push, ECS deploy, health check

**Track 2 — Infra CD (CDK Pipelines):**

```
Source → Synth → cdk-nag (AWS Solutions + HIPAA) → Staging → Manual Approval → Production
```

Self-mutating CodePipeline — updates itself when `infra/` changes. ManualApprovalStep provides CC8.1 change management evidence.

## Edge security

The AWS architecture adds two layers of protection not present in the current stack.

### CloudFront

- Edge caching for `_next/static/*` (immutable, 365-day TTL) and images
- Dynamic routes (SSR, API) pass through uncached — all cookies forwarded for BetterAuth sessions
- Shield Standard (free L3/L4 DDoS protection)
- ALB security group restricts inbound to CloudFront managed prefix list

### AWS WAF

| Rule | Protection |
|------|-----------|
| Rate limiting | 1000 requests per 5 minutes per IP |
| AWSManagedRulesCommonRuleSet | SQL injection, XSS, path traversal |
| AWSManagedRulesKnownBadInputsRuleSet | Log4j, Spring4Shell exploits |
| AWSManagedRulesSQLiRuleSet | Advanced SQL injection patterns |
