## Specs

Feature specifications live in `.claude/specs/`. Each spec directory contains:

| File | Purpose |
|------|---------|
| `requirements.md` | What to build — user stories, acceptance criteria |
| `design.md` | How to build it — architecture, data model, API design |
| `tasks.md` | Implementation checklist, phased |

To create a new spec, use the templates at `.claude/specs/{requirements,design,tasks}.md`. Check [SPECLOG.md](https://github.com/verity-aml/verity/blob/main/SPECLOG.md) for the current implementation status and which spec to work on next.

## Skills (slash commands)

### Planning

| Command | Description |
|---------|-------------|
| `/session-start` | Load project context — reads specs, changelog, git history, produces prioritised briefing |
| `/plan brainstorm <topic>` | Explore idea, write plan to `docs/plans/` |
| `/plan interview [slug]` | Read plan, deep interview, write specs to `.claude/specs/` |
| `/plan visualize [slug]` | Generate Mermaid diagrams from spec for visual design validation |
| `/plan review [slug]` | Validate specs (architecture, quality, tests, performance) |
| `/plan-ceo [slug]` | CEO-mode plan review — 10-star product thinking, premise challenge |
| `/execute [spec or issue]` | Task-by-task execution with subagents + two-stage review |

### Shipping and review

| Command | Description |
|---------|-------------|
| `/ship` | Full release pipeline — merge main, test, simplify, review, bisectable commits, push, PR |
| `/ship pr-only` | Lightweight PR — skip tests/review, just commit + push + create PR |
| `/ship clean` | Clean up stale local branches marked as `[gone]` on remote + worktrees |
| `/review` | Pre-landing review — 5 core + 2 conditional agents, confidence scoring |
| `/review pr <number>` | Review existing PR — posts findings as PR comment (read-only) |
| `/review pr 1,2,3 --multi` | Spawn separate Claude Code instances in tmux panes — context-free unbiased reviews |
| `/review [pr N] --converse codex` | Adversarial review — both models review in parallel, then debate until consensus |
| `/receiving-pr-feedback [pr]` | Handle PR review feedback — verify before implementing, push back when wrong |
| `/babysit-pr <number>` | Watch PR through CI — poll checks, retry flaky CI, macOS notifications |
| `/qa [url] [--quick]` | Systematic QA testing — diff-aware, design system checks, multi-tenancy validation |

### Debugging and quality

| Command | Description |
|---------|-------------|
| `/debug [error]` | Systematic 4-phase debugging: investigate, patterns, hypothesis, fix |
| `/prevent [description]` | Analyse a mistake, find deterministic prevention, implement guardrail + tracking issue |
| `/simplify` | Review changed code for reuse, quality, and efficiency |
| `/eval-parser` | Run parser golden set evaluations — required before prompt changes |
| `/lint-rule-gen [desc]` | Generate ESLint or agent-rules from review feedback patterns |

### Scaffolding

| Command | Description |
|---------|-------------|
| `/new-api-route <name>` | Scaffold Next.js API route + Vitest test with auth guard, org scoping |
| `/new-spec <slug>` | Scaffold spec directory (requirements.md, design.md, tasks.md) + SPECLOG row |
| `/skill-builder <name>` | Scaffold a new skill with best-practice structure |
| `/worktrees [branch]` | Create isolated git worktrees with auto project setup |

### Operations and data

| Command | Description |
|---------|-------------|
| `/update-docs` | Update all project documentation after changes |
| `/sweep-issues` | Scan session for deferred items — auto-create GitHub issues |
| `/retro [window]` | Weekly engineering retrospective — commit analysis, trends |
| `/seed-demo <org>` | Seed demo compliance programs with realistic scoring data |
| `/unseed-demo <org>` | Remove demo-seeded compliance data |
| `/delete-org <org>` | Permanently delete an organisation and all related data |

### Session guards

| Command | Description |
|---------|-------------|
| `/careful` / `/careful off` | Block destructive commands (force push, rm -rf, DROP TABLE) for the session |
| `/freeze <dir>` / `/freeze off` | Restrict edits to a specific directory for the session |
| `/context7 [lib] [query]` | Look up current, version-specific library documentation |

### Plugin skills

`/commit`, `/review-pr`, `/revise-claude-md`, `/claude-md-improver`, `/hookify`, `/hookify:list`, `/hookify:configure`

## Agents

| Agent | Trigger | Description |
|-------|---------|-------------|
| `context-loader` | Start of session | Reads specs, SPECLOG, git log, CHANGELOG. Produces a prioritised briefing. |
| `doc-updater` | End of session | Updates docs, SPECLOG, CHANGELOG, and task tracking after work is done. |
| `browser` | Visual testing | Browser automation for screenshots, navigation, form filling, and visual verification. |
| `code-reviewer` | Pre-commit (automatic) | Reviews staged changes against CLAUDE.md conventions, active spec, and codebase patterns. |

## Hooks (automatic)

These run automatically via `.claude/settings.json` — no manual invocation needed.

### PreToolUse (before actions)

- **Review gate** blocks `git commit` until staged changes pass the `code-reviewer` agent (skip with `[skip-review]`, `docs:`, `chore:` prefixes)
- **Lint gate** checks `agent-rules.json` patterns against staged files (bypass with `[skip-lint]`)
- **Deferred items guard** blocks commits when `.claude/.deferred-items` has content
- **Doc guard** blocks creation of random `.md` files outside known locations
- **tmux** reminders for long-running commands; blocks dev server outside tmux
- **Push guard** blocks direct pushes to main/master
- **On-demand runner** enforces session rules from `/careful` and `/freeze`
- **Strategic compact** suggests `/compact` at logical intervals to manage context

### PostToolUse (after actions)

- **Prettier** auto-formats JS/TS files after edits
- **TypeScript** type-checks after editing `.ts`/`.tsx` files
- **ESLint** checks on edited files — reports violations for self-correction (fail-open)
- **console.log** warnings after edits
- **Babysit-pr** auto-spawns CI monitor daemon after `gh pr create`
