Bank-readiness scoring maps regulatory requirements to scoring criteria by compliance domain, tracks evidence status, and computes readiness scores. Each criterion links to its regulatory source in the knowledge base.

## How scoring works

The scoring model is a three-tier hierarchy: **Program** → **Domain** → **Criteria**.

- **Programs** are scoped by regulation type — BSA/AML maps to 5 FFIEC pillars, Third-Party Oversight maps to 8 OCC 2023-17 monitoring areas
- **Domains** correspond to regulatory categories (e.g., Internal Controls, Independent Testing)
- **Criteria** have an evidence status: `missing`, `partial`, or `sufficient` — auto-derived from the criterion's score

### Score formula (v2 — novelty-weighted additive)

Scoring rewards **diverse** evidence, not just more evidence. Each piece of evidence linked to a criterion is compared against all previously linked evidence using cosine similarity on Voyage AI embeddings:

```
contribution = 100 × (1 − max_similarity_to_prior_evidence)
criterion_score = sum(contributions)
domain_score = sum(criterion_scores)
program_score = sum(domain_scores)
```

- **First evidence** linked to a criterion contributes **100 points** (full novelty)
- **Near-duplicate** evidence (high cosine similarity to existing) contributes close to **0 points**
- **Non-embeddable** evidence (binary files, failed extraction) contributes a flat **50 points**
- Scores are **unbounded integers** — a team that thoroughly documents a domain will show it

Evidence status is auto-derived from `criterion_score`: **0 = missing**, **< 100 = partial**, **≥ 100 = sufficient**. You cannot set evidence status manually — the PATCH criteria route rejects manual `evidenceStatus` updates.

### Per-domain configurable thresholds

Each domain has an optional `threshold_pct` (1–100) that replaces the former global threshold. Admins set readiness targets per domain via an inline slider on the domain detail page. Threshold-crossed notifications fire per-domain using each domain's configured target. Domains without a threshold configured display scores as raw points.

## Criteria table

The domain detail page lists every scoring criterion, each one mapped to a specific section of regulatory guidance:

| Column | Description |
|--------|-------------|
| Criterion text | What the regulation requires |
| Regulatory source | The specific FFIEC section or OCC 2023-17 paragraph |
| Evidence count | How many documents are linked |
| Evidence status | Missing, Partial, or Sufficient (auto-derived from criterion score) |

Each row also shows the **criterion definition key** (e.g., `ic-01`, `tr-03`) in the Source column above the regulatory source link, making it easy to cross-reference with parsed examination items.

Evidence status is auto-derived from the criterion's novelty-weighted score, so it updates automatically as evidence is linked or unlinked. You can still add reviewer notes and manage linked evidence manually.

<Warning>
Criteria with a **REQUIRES REVIEW** warning beneath the status dropdown have been auto-matched with evidence and set to "sufficient" by the system, but no human has confirmed them yet. The warning clears when you change the status or add reviewer notes.
</Warning>

## Reviewer notes and history

Click **Expand** on any criterion to reveal two tabs: **Evidence** and **History**.

The **Evidence** tab shows reviewer notes (auto-saved after a one-second pause) and linked evidence documents.

The **History** tab is the audit trail — a scrollable, filterable log of every change to this criterion. Who changed the status, when, and why. System-generated entries from auto-match are logged as "System." Filter by change type (status, evidence, notes) to find what you need.

## Domain-level evidence upload

Above the criteria table, a **drag-and-drop upload zone** lets you upload evidence files directly to the domain without going through an examination workflow. Multiple files are supported with per-file progress indicators.

After upload, the system auto-suggests the uploaded evidence against all criteria in the domain. Unlinked files appear in an expandable section, and you can manually assign them to specific criteria using the **Link Evidence** dropdown on any criterion's Evidence tab.

## Auto-matching

The **Find Evidence** button in the domain detail page header bridges examination workflow and compliance program scoring.

Click "Find Evidence" to open a dialog listing your organization's examinations with checkboxes. Select individual examinations or use **Select All**, then click **Match Selected**. The system scans each selected examination's request items and attached evidence against the criteria in the current domain.

From the dashboard, the **Run Gap Analysis** button matches evidence from all examinations across all domains at once.

Matching uses two signals:

1. **Direct criterion key** — if a request item has a scoring criterion key (like `ic-01`) that matches a criterion's definition key, that's an exact match
2. **Regulatory source alignment** — if a request item and a criterion both reference the same FFIEC section, the evidence is relevant

When evidence is auto-linked, the system recomputes the criterion's novelty-weighted score and updates the evidence status accordingly. The **REQUIRES REVIEW** warning appears until a human confirms. This is opt-out, not opt-in — the system attaches evidence it considers relevant, and you remove anything that doesn't belong.

### Evidence embedding pipeline

All evidence uploads compute a SHA-256 content hash (preventing identical files from being linked twice to the same criterion) and dispatch to the `embed-evidence` SQS queue. A Lambda downloads the file, extracts text, and generates a `voyage-law-2` embedding. This embedding is what powers the novelty-weighted scoring — each new piece of evidence is compared against existing linked evidence to determine how much novel information it adds.

### Trends page

Navigate to **Trends** from a compliance program to see score history over time. The trends page shows Recharts line charts with date range presets (7d/30d/90d/180d/1y), auto-bucketing (daily/weekly/monthly), and domain filtering with URL state. A paginated score events table below the chart shows individual score-affecting events. Historical v1 percentage scores (from before the scoring engine v2 migration) render as a dashed series on a secondary axis.

Auto-matching turns examination evidence into reusable compliance proof. Evidence uploaded for one examination cycle can strengthen your readiness score across future cycles.
